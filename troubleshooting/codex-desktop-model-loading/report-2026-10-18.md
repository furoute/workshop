- 记录人：🐾 dsh-desktop（DSH@台式机）
- 日期：2026-10-18
- 机器：<hostname>（Windows 11，AMD64）
- 相关软件：ChatGPT/Codex 桌面端 `26.1013.40934`（MSIX），Codex CLI `0.163.0-alpha.10.2`

---

## 0. 结论摘要

> **不是 DeepSeek 配置坏了，是桌面端的「模式 + 登录态 + 模型记忆」三者叠加死锁。**

一句话因果链：

```
桌面端升级到 26.1013（10-16）
  → free 账号下 codexLocalAccess = false，UI 强制落到 ChatGPT Work 模式
  → Work 模式要求 ChatGPT 账号身份
  → 但 auth.json 已过期/丢失，且 forced_login_method="api" 把登录入口堵死
  → Work 模式下要用 OpenAI 模型初始化会话，而 provider 指向 DeepSeek
  → 表现为「正在加载模型」/ `Work browser access requires an authenticated account`
```

## 1. 现象

| 场景 | 表现 |
|---|---|
| 打开旧会话 | 左下角转圈「正在加载模型」，无法输入 |
| 新建会话 | 同上；偶发红条 `继续聊天未成功 / Work browser access requires an authenticated account` |
| CLI | **完全正常**，`codex exec` 返回正常文本 |
| 切换模式 | 左上角显示 `ChatGPT Work`；在 Codex 模式下打开会话正常，切到 Work 后再打开就报错 |

关键观察：**报错只发生在「用 Work 模式冷启动一个会话」时**；先在 Codex 打开、再切 Work 不会报错（会话已用 DeepSeek 初始化完成，切模式只是换 UI 视图）。

## 2. 配置基线（本身是正确的）

```toml
model_provider = "deepseek"
model = "deepseek-flash"
model_catalog_json = "C:/Users/<user>/.codex/models.json"
model_reasoning_effort = "low"

[model_providers.deepseek]
name = "deepseek"
base_url = "https://api.deepseek.com/"
wire_api = "responses"
experimental_bearer_token = "<redacted>"

[desktop]
conversationDetailMode = "STEPS_PROSE"   # ← 关键：Work 模式残留值
```

`models.json` 含 `deepseek-flash` 与 `deepseek-v4-pro` 两个条目，JSON 合法。

DeepSeek 官方一键脚本（`https://cdn.deepseek.com/api-docs/codex-deepseek-setup.ps1`，v1.4.0）只负责写上面这两处，**不涉及桌面端模式**，因此重跑脚本无法修复本问题。

## 3. 根因（四个故障点）

| # | 故障点 | 证据 |
|---|---|---|
| 1 | `home-composer-mode-v1 = "work"`（`.codex-global-state.json`） | 左上角始终 `ChatGPT Work` |
| 2 | `auth.json` 不存在，8 月 token 已过期 | `codex login status` 返回 `Not logged in` |
| 3 | `forced_login_method = "api"` | `codex login` 直接报 `ChatGPT login is disabled. Use API key login instead.` |
| 4 | `chatgpt-last-selected-model-v1 = {"slug":"gpt-5-5"}` | 每次打开会话把模式拽回 Work |
| 5（旧会话） | 会话 `model` 为 `deepseek-v4-flash` | v1.4.0 已移除该 slug，只能 fallback |

### 代码层定位

在 `resources/app.asar` 中搜索到判定逻辑：

```js
// 模式选择
let t = detailMode === 'STEPS_PROSE' ? 'chatgpt_work' : 'codex';
return n.status === 'loading' ? t
     : n.codexLocalAccess ? (...) : 'chatgpt_work';

// 报错条件
if (local && requireWorkBrowserIdentity && mcp_servers.node_repl != null && principal == null)
    throw Error('Work browser access requires an authenticated account');

// requireWorkBrowserIdentity 的来源
requireWorkBrowserIdentity: (conversationDetailMode === 'STEPS_PROSE')
```

`conversationDetailMode` 合法值只有 `STEPS_PROSE` / `STEPS_COMMANDS` / `STEPS_EXECUTION`，默认 `STEPS_COMMANDS`。`STEPS_PROSE` 是 Work 模式专用。

## 4. 排查路径（可复用）

1. **先分诊**：用 CLI 跑一次 `codex exec "只回复 OK"`。CLI 正常 → 配置/provider/API key 无罪，问题在桌面端 UI 层。
2. **读客户端日志**：`~/.codex/logs_2.sqlite` 的 `logs` 表，关注 `codex_login`、`remote_control`、`codex_models_manager`、`codex_core_plugins`。
3. **反查报错文案**：在 `C:\Program Files\WindowsApps\OpenAI.Codex_*\app\resources\app.asar` 中按字节搜索错误字符串，定位触发条件（asar 是未压缩归档，可直接 grep）。
4. **核对登录态**：`codex login status`；解码 `auth.json` 的 JWT claims 看 `chatgpt_plan_type`（本次为 `free`）。
5. **核对客户端版本时间线**：从日志中提取 `client_version=`，确认升级时间点。
6. **对比旧备份**：`config.toml.dshbak-*` 可看出设置何时被改。

## 8. 注意事项

- **重跑 DeepSeek 官方脚本会把 `forced_login_method = "api"` 写回**，从而再次禁掉 ChatGPT 登录。以后若要重新登录，需先删/注释这一行。
- `#37245` 提示：登录 ChatGPT 账号后，自定义 provider 可能被静默忽略，请求走账号 websocket。验证方法：发消息后看 DeepSeek 平台是否扣 token。
- `STEPS_PROSE` 是 Work 模式专用值，普通 Codex 用户建议保持 `STEPS_COMMANDS`。
- 修改 `.codex-global-state.json` 前务必重复备份，它同时保存窗口、项目、草稿等大量 UI 状态。
