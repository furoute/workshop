# Everything 正则表达式参考

> Everything 1.4 内置完整 PCRE 风格正则，无需插件。
> **最重要的坑：正则作用于「完整路径 + 文件名」，不是只对文件名。**

## 一、最要命的一条

```
❌ "D:\项目资料\" regex:汇报.*\.pptx$      → 0 命中
✅ "D:\项目资料\" regex:.*汇报.*\.pptx$     → 82 命中
```

加了路径限定后，正则串开头是盘符 `D:`，`汇报` 永远对不上。
所以**必须用 `.*` 把路径吃掉**。`^` 在带路径限定的查询里等于匹配盘符，不是文件名开头。

## 一之二、完整元字符表（官方）

```
a|b          匹配 a 或 b
gr(a|e)y     匹配 gray 或 grey
.            匹配任一字符
[abc]        匹配 a 或 b 或 c
[^abc]       匹配除 a,b,c 外的任一字符
[a-z]        匹配 a 到 z
[a-zA-Z]     匹配 a-z 及 A-Z
^            匹配文件名开头
$            匹配文件名结尾
( )          捕获组
\1..\9       引用第 n 个捕获组
\b           词边界
*            前项 0 或多次
?            前项 0 或 1 次
+            前项 1 或多次
*?  +?       懒人模式
{x}          前项恰 x 次
{x,}         前项 >= x 次
{x,y}        前项 x 到 y 次
\            特殊字符转义
```

写法：`regex:模式`，可与普通词、路径、属性前缀叠加。

## 二、常用元字符

| 写法 | 含义 | 例子 |
|---|---|---|
| `.` | 任意单字符 | `报告.` |
| `.*` | 任意长度（含 0） | `.*方案.*\.pdf$` |
| `.+` | 至少 1 个字符 | `.+报告` |
| `\d` | 数字 | `20\d{2}` |
| `\w` | 字母数字下划线 | `SR\w+` |
| `\s` | 空白 | `\d+\s\d+` |
| `[abc]` | 字符集 | `[Pp]df` |
| `[^abc]` | 排除字符集 | `[^\d]` |
| `(a\|b)` | 分组或 | `(pdf\|docx)` |
| `{n}` `{n,m}` | 重复次数 | `\d{4}` |
| `^` `$` | 首/尾锚点（配合完整路径用 `$` 可靠） | `.*\.pdf$` |

## 三、实测通过的写法

```bash
# 所有以「中标通知书」结尾的 PDF（注意 $ 锚点和扩展名要一起写）
regex:.*中标通知书.*\.pdf$

# 2024 年后改过的 pptx 报告
regex:.*汇报.*\.pptx$ dm:>2024

# 服务报告：SR号 空格 Task号 开头
path:"<目录>\" regex:.*^\d+\s\d+\s.*

# 带版本号的文档
regex:.*V\d+.*\.docx$ dm:>2025

# 换盘记录图片
regex:.*replace.*disk.*\.tif$
```

## 四、实测失败 / 有陷阱的写法

| 写法 | 结果 | 原因 / 替代 |
|---|---|---|
| `regex:汇报.*\.pptx$`（带路径限定） | 0 命中 | 缺 `.*` 前缀 |
| `regex:.*报告.(pdf\|docx)$` | 不稳 | `$` + 分组组合容易静默失败，改用 `ext:` |
| `(20\d{2})[.\-年](0?[1-9]\|1[0-2])` | 0 命中 | 嵌套分组 + 字符集连字符不稳 |
| `regex:.*<A\|B>.*` | 报错 | `< >` 是 Everything 分组符，正则内用 `( )` |
| `regex:2022\..*` | 误命中 | `.` 未转义，会匹配 `2022年` `2022-`；写 `2022\.` |
| `dm:thisweek` | 0 命中 | 不支持，用 `dm:7days` / `dm:today` |

## 五、什么时候该用正则

**能用关键词就别用正则。** 实测对比（同一意图，都是 82 命中、0.03 秒）：

```
"D:\项目资料\" regex:.*汇报.*\.pptx$ dm:>2024     → 82
"D:\项目资料\" 汇报 ext:pptx dm:>2024            → 82   ← 更好写
```

正则真正值得用的三种情况：

```
① 要匹配固定格式（SR 号格式、日期格式、版本号）
② 要精确限定文件名首/尾
③ 要排除特定模式
```

## 六、和通配符的分工

```
* ?     简单模糊匹配 → 够用就用这个
regex:  复杂模式       → 上面的三种情况再上
```

不要在同一条查询里混用：写了 `regex:` 之后，同一个词项里的 `*` 会被当正则量词。
需要限定扩展名就另起 `ext:` 词项。
